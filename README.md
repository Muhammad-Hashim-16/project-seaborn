## Getting Started

Follow these steps to set up and run SeabornGallery locally:

1. **Clone or download** this repository

2. **Place your `master_plots.py` file** inside the `src/` folder. This is the master file containing all 65 seaborn plots.

3. **Ensure your plot markers** follow the format:
   ```python
   # 1 Scatter Plot
   # 2 Line Plot
   # 3 Bar Plot
   ```
   Each marker starts with `#` followed by a space, then the plot number, then a space, then the plot name.

4. **Ensure datasets are loaded once** at the top of `master_plots.py` as `_base_*` variables:
   ```python
   _base_tips = sns.load_dataset("tips")
   _base_flights = sns.load_dataset("flights")
   ```

5. **Install dependencies** if needed:
   ```bash
   pip install matplotlib seaborn numpy pandas
   ```

6. **Run the splitter**:
   ```bash
   python splitter.py
   ```

7. **Check the output** — the following will be generated:
   - `figures/` — PNG images of each plot
   - `code_snippets/` — Raw Python code for each plot
   - `data.json` — Metadata array for the web gallery

8. **If any plots failed**, check `failed_plots.json` for error details and fix them in your `master_plots.py`.

9. **Run the naming script** to generate AI tag prompts:
   ```bash
   python generate_names_prompt.py
   ```

10. **Open `naming_prompts.txt`** and follow the instructions — copy each batch prompt into an AI chatbot (like ChatGPT or Claude) to get tag suggestions.

11. **Save all AI responses** into `ai_responses.json` as a single JSON array, then merge:
    ```bash
    python generate_names_prompt.py --merge
    ```

12. **Open `index.html` with a local server** (e.g., VS Code Live Server extension):
    > ⚠️ Do NOT open `index.html` by double-clicking — the `fetch()` API requires a server to work.

## PWA Icons

To make the PWA installable with proper icons:

1. Replace the placeholder icons in `icons/` with real PNG icons at the listed sizes:
   - 72×72, 96×96, 128×128, 144×144, 152×152, 192×192, 384×384, 512×512

2. **Recommended tool**: [RealFaviconGenerator](https://realfavicongenerator.net/) — upload a high-res image and it will generate all sizes.

3. Also add a `profile.jpg` to the project root for the about page.

## Customization

After running the splitter and generating your gallery, customize the following:

### Personal Details (about.html)
Search for `[ACTION]` comments in `about.html` and fill in:
- Your full name
- Your role / title
- Your city and country
- A short bio
- Email address
- LinkedIn URL
- GitHub URL

### GitHub Link (both pages)
Update the GitHub icon link in the navbar of both `index.html` and `about.html`:
```html
<!-- [ACTION]: Add your GitHub URL here -->
<a href="https://github.com/yourusername/seaborn-gallery" ...>
```

### Copyright
Update the copyright text in the footer of both pages if needed.

## Deployment

### Vercel (Recommended)
1. Push your project to a GitHub repository
2. Connect the repo to [Vercel](https://vercel.com)
3. Set the root directory to the project folder (e.g., `seaborn-gallery/`)
4. No build command is needed — this is a static site
5. Set the output directory to `/`
6. Deploy!

### GitHub Pages
1. Push the repository to GitHub
2. Go to **Settings** → **Pages**
3. Set source to "Deploy from a branch"
4. Select the `main` branch and root directory `/`
5. Save and wait for deployment

### Subdirectory Deployment Note
If deploying to a subdirectory (e.g., `username.github.io/seaborn-gallery/`):
- Update `scope` in `sw.js` to match your subdirectory
- Update `start_url` and `scope` in `manifest.json`

## Notes

- This gallery was built with **Python** and **seaborn** — all 65 plots are executed and rendered by the splitter script.
- The `splitter.py` script automatically extracts plot names from the `# N Plot Name` comments in `master_plots.py`.
- **Difficulty levels** are determined from `PHASE` headers in the master file:
  - `# PHASE 1` → Beginner (Plots 1–20)
  - `# PHASE 2` → Intermediate (Plots 21–40)
  - `# PHASE 3` → Advanced (Plots 41–65)
- All datasets are loaded once at the top of the master file to prevent redundant network requests.
- The web gallery is a **static frontend-only application** — no backend server is required.
- **Search** supports fuzzy matching with Levenshtein distance, multi-word AND queries, and tag/difficulty filtering.
